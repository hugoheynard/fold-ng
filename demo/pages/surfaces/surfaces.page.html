A named surface re-points some semantic role tokens for its sub-tree, so any component inside resolves its colours against the region's palette — with no per-component code. It's stamped with [data-surface="…"] (via the foldSurface directive, or a component's own host binding). Two ship: chrome (app furniture a mixed theme recolours) and accent (an auto-inverting accent fill).

The design system isn't a cage — it's a set of relationships. Writing your own CSS in a card is always free: raw values don't reference the roles, so a surface never touches them. An override isn't a hack — it re-anchors one relationship (text ↔ ground ↔ accent) inside a controlled frame, and coherence follows because the ratios are preserved. You speak in roles and gain the adaptation, or you paint a pixel and own it — both live in the same card.

Identical markup in both cards. On the accent one, the icon tile, text, the raised/separated header, the badge, the link and both buttons all read on the accent — because the region re-points the roles they already resolve against, not because the card special-cases any of them.

Why it can't be a flat override. An inverting surface must swap the brand pair — primary becomes the light ink, on-primary becomes the accent. Written on one element that's a CSS custom-property cycle (a: var(b); b: var(a) → both invalid). It's the wall a naïve "just set color + background" hits the moment you nest a badge, a link, or a solid button.

The move: capture on the surface, invert on the descendants. The surface records the accent + its ink into two private vars while the tokens still hold their normal values; the inverted role-set is applied to descendants from those captures — so a role can reference the pre-inversion value it replaces. No cycle, and every value is a color-mix of the captured pair, so it's derived, not authored: one definition holds on all five themes, gradation kept in-hue.

An accent card is an emphasis surface: a mid-bright accent caps white text near 3:1, so the text ramp is compressed and the floor is AA-large (3:1) — reaching AA-body (4.5) would mean darkening the brand accent, a deliberate no. A WCAG contrast test resolves every theme's accent and fails the build if the on-accent text drops below its floor. Certified, not eyeballed.

The derived defaults are good, not sacred. If a theme's accent is light and the light-ink ramp reads thin, override any role by nesting the theme's own selector under the surface — the same seam chrome uses. Re-pointing --_accent-ink / --_accent-fill is the cheapest lever (the whole ramp follows); re-point one --fold-color-* when only that role must move.
