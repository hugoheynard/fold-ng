fold-calendar-month — a month grid on a date axis, where an event is a band stretching from the column it starts on to the column it ends on. A span crossing a week is drawn once per week with an open edge on the side that continues, so a three-week holiday reads as one thing rather than twenty-one chips. Dates are plain YYYY-MM-DD strings, never Date — see “plain dates”.

lane budget · each crowded day says how much it lost

A hidden span counts against every day it would have covered, so the chip sits in the column that actually lost something rather than at the end of the row. It emits that day — last: “{{ lastOverflow() ?? "—" }}”.

grouping · one chip, the union of its members

Four people, four different ranges, one band: events sharing a groupId collapse and the chip spans everything it stands for.

composability · every container is a template, not just the chip {{ day.dayOfMonth }} @if (isHoliday(day.date)) { closed } {{ event.label }} @if (band?.continuesAfter) { … } {{ count }} hidden

Three templates, no CSS override: foldCalendarDay replaces the cell's inside (here a “closed” flag on two public holidays), foldCalendarEvent replaces the chip — typed, so let-band knows about continuesAfter — and foldCalendarOverflow replaces the +N. dayModifiers puts the app's own names on the cell as data-fold-day-modifiers, matchable with [data-fold-day-modifiers~="holiday"].

Clicking a day drills into it — which is not decoration: bands are aria-hidden (they span columns, so they cannot be grid cells), so dayClick is the keyboard route to an event.
